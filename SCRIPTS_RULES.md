# Правила PowerShell-скриптов

Эти правила обязательны для работы Codex с PowerShell в данном репозитории. Цель — использовать короткие неизменные команды запуска, чтобы одно постоянное разрешение применялось повторно.

## 1. Расположение и повторное использование

1. Все проектные PowerShell-скрипты размещаются только в `ps_scripts/`.
2. Перед созданием скрипта нужно проверить существующие файлы и расширить подходящий скрипт, если он уже решает похожую задачу.
3. Повторяемая или многошаговая операция оформляется одним скриптом, выполняющим законченную задачу.
4. Длинные одноразовые команды PowerShell не используются, если их можно заменить существующим или универсальным скриптом.

## 2. Неизменная команда запуска

1. Скрипт, которому требуется постоянное разрешение, запускается без динамических параметров:

   ```powershell
   .\ps_scripts\Edit-RepositoryFiles.ps1
   ```

2. Имена файлов, строки поиска и замены, режимы и другие изменяемые данные передаются через файл задания в `ps_scripts/`, а не через аргументы командной строки.
3. Запрещено передавать задания через `-OperationsBase64`, длинные JSON-строки, here-string или другие меняющиеся аргументы: они превращают каждый запуск в новую команду и вызывают повторное разрешение.
4. Для каждой категории операций используется одна стабильная команда. Новые параметры добавляются в формат файла задания, а не в командную строку.
5. Скрипт без изменяемых параметров запускается напрямую, без ненужного файла задания.

## 3. Файлы заданий

1. Файлы заданий находятся только в `ps_scripts/` и имеют постоянные имена: `edit_operations.json`, а при необходимости `build_task.json` или `git_task.json`.
2. Локальные файлы заданий перечисляются в `.gitignore` и не попадают в commit или GitHub.
3. Перед запуском Codex полностью перезаписывает файл задания; добавлять новую задачу к старому содержимому нельзя.
4. После успеха файл задания удаляется или очищается. При ошибке его можно временно оставить для диагностики, но перед следующей операцией он полностью перезаписывается.
5. Файл задания содержит только данные. Произвольные команды PowerShell, `cmd`, shell-выражения и исполняемый код запрещены.

Формат `ps_scripts/edit_operations.json`:

```json
[
  {
    "path": "relative/path/from/repository/root.cs",
    "find": "exact old text",
    "replace": "exact new text",
    "count": 1
  }
]
```

`path` задаётся относительно корня репозитория. `count` — точное ожидаемое число совпадений. Несовпадение является ошибкой и отменяет весь пакет.

## 4. Безопасность

1. Корень репозитория определяется относительно `$PSScriptRoot`; абсолютный путь к пользовательской рабочей папке в скрипте запрещён.
2. Каждый путь преобразуется в абсолютный и проверяется: он обязан оставаться внутри репозитория либо заранее определённого безопасного каталога, например `newbins`.
3. Скрипты не выполняют произвольный текст команды. Допустимые действия задаются кодом скрипта и ограниченным списком операций.
4. До первой записи проверяются все операции. Если одна операция недопустима, целевые файлы не изменяются.
5. Обязательны `$ErrorActionPreference = 'Stop'`, `Set-StrictMode -Version Latest`, понятные сообщения и ошибка при неудаче.
6. Повторный запуск должен быть безопасным. Разрушительные действия требуют проверки точного пути и области.
7. Повышение прав не запрашивается без реальной необходимости.
8. Пароли, токены, реальные HWID, приватные URL подписок, содержимое `hwid`, загруженные конфигурации и другие секреты запрещены в скриптах, заданиях и Git.

## 5. Порядок работы Codex

1. Прочитать существующий скрипт и проверить его область действия.
2. Создать или полностью перезаписать игнорируемый файл задания.
3. Кратко сообщить предполагаемые изменения.
4. Запустить стабильную команду без параметров.
5. Проверить код завершения и вывод.
6. Просмотреть `git diff --check`, `git diff` и `git status`.
7. Запустить нужные тесты или сборку через существующие стабильные скрипты.
8. Не выполнять commit и push без отдельной явной команды пользователя.

При внутренней ошибке песочницы, например `helper_unknown_error`, Codex сначала повторяет ту же разрешённую команду или ждёт восстановления среды. Нельзя автоматически переходить к новой длинной команде с отдельным запросом.

## 6. Git, тесты и сборка

1. Состояние проверяется через `ps_scripts/Git-Status.ps1` или короткие стандартные Git-команды.
2. ServiceLib тестируется через `ps_scripts/Test-ServiceLib.ps1`.
3. Release и `newbins` собираются через `ps_scripts/Build-ReplacementBins.ps1`.
4. Стабильные команды не заменяются длинными эквивалентами.
5. В Git добавляются только явно проверенные пути; `git add .`, `git add -A` и `git add --all` запрещены.
6. Файлы заданий, `hwid`, ссылки подписок, полученные JSON и `newbins` в Git не добавляются.

## 7. Новые разрешения

Новый запрос допустим только для новой категории действий, которую объективно не покрывает ранее разрешённый ограниченный скрипт или команда. Изменение имени файла, текста замены или другого значения в файле задания не является новой категорией и не должно создавать новый запрос.
